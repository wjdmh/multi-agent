MY_AGENT.PY · WORKFLOW

이 에이전트는 어떻게 일하는가

입력을 모아 정리하고, 점수 매겨 줄 세우고, AI로 보강하고, 스스로 검토해서 부족하면 다시 찾아오는 — 8단계 파이프라인

💡 비유하자면, "신문 스크랩 + 정리 + 검수까지 하는 비서" 같은 구조입니다

텔레그램 전송
1

자료 모으기 extract_facts / fetch_external_context

두 곳에서 자료를 가져옵니다 — 코드에 미리 넣어둔 내부 샘플(논문·뉴스·이론·케이스·용어)과, 구글 뉴스 RSS·PubMed에서 실시간으로 가져오는 외부 자료.

가져온 텍스트를 그대로 쓰지 않고 {type, title, content, keywords...} 딕셔너리로 정리합니다 — 이게 "중간 정보"입니다.

🗂️ 비유: 신문에서 기사를 오려서 "제목 / 내용 / 분야" 칸이 있는 카드에 옮겨 적는 작업
2

중요도 점수 매기기 score_relevance

각 자료에 0~10점을 매깁니다. 도메인 키워드가 많을수록, 보강이 필요할수록, 외부 최신 자료일수록 점수가 올라갑니다.

점수 높은 순으로 정렬해서 중요한 자료부터 처리합니다.

3

AI로 보강 enrich_facts

점수 상위 6개를 LLM에 보내 한국어 요약·중요한 이유·핵심 포인트·현장 적용 팁을 받아옵니다.

⚙️ API가 없거나 실패해도 규칙 기반 보강(enrich_rule_based)이 대신 작동 — 실행이 멈추지 않습니다.

4

카테고리 분류 classify_items

키워드를 보고 5개 카테고리(이론·운동처방·병태생리·액티브에이징·지도론) 중 하나에 자동으로 배치합니다.

예: 키워드에 "고혈압"이 있으면 → 병태생리_및_질환관리로 분류
5

보고서 작성 write_output / write_user_guides

분류된 자료로 output.md(데이터 표)와 output_user_guide.md(상황별 학습 가이드 + 오늘의 핵심 TOP 3)를 만듭니다.

6

스스로 검토 review_guides

완성된 가이드를 다시 점검합니다 — 자료가 부족한 섹션은 없는지, "무조건"·"100%" 같은 위험한 단정 표현이 있는지, 안내 대상이 명확한지.

LLM 검토가 가능하면 Gemini가, 실패하면 규칙 기반 체크리스트가 대신합니다.

7

부족하면 재수집 needs_refetch 피드백 루프

검토 결과 자료가 부족하다고 판단되면, 다른 검색어로 한 번 더 외부 자료를 가져와서 보고서를 다시 작성합니다.

📍 이 부분이 "결과를 보고 스스로 보완하는" 적응형 동작입니다
8

텔레그램 전송 send_to_telegram

완성된 가이드를 "브리핑 도착 📬" 머리말과 함께 전송합니다. 4096자가 넘으면 자동으로 여러 메시지로 쪼개서 순서대로 보냅니다.

핵심 요약

"점수를 매겨 줄 세우고 → 분류하고 → AI로 보강하고 → 검토하고 → 부족하면 다시 찾아오는"
모든 판단을 코드가 직접 합니다. AI는 보조 역할일 뿐입니다.
그래서 단순 챗봇이 아니라 "에이전트"로 분류됩니다.

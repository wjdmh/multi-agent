# Week 12. 내 에이전트 1차 개선: 핵심 정보 추출과 분류

> 11주차에 만든 `my_agent.py`를 개선한다.
> 

> 강의자료의 일정공지 에이전트는 공통 예시이고, 학생은 본인이 선택한 주제에 맞게 추출 항목과 분류 기준을 바꾼다.
> 

> 기본형은 규칙 기반으로 완성한다. 선택 확장으로 Groq API 또는 외부 도구 1개를 붙일 수 있다.
> 

---

## 학습 목표

- 내 입력 자료에서 핵심 정보를 추출한다.
- 추출 결과를 리스트와 딕셔너리 형태로 정리한다.
- 내 에이전트의 “정보 추출자”와 “분류자” 역할을 개선한다.
- 결과를 `output.md`에 Markdown 표로 저장한다.
- Groq API 또는 외부 도구를 어디에 붙일 수 있는지 판단한다.
- 코딩에이전트에게 작은 단위로 수정 요청하는 방법을 익힌다.

---

## 이번 주 핵심 원칙

1. 새 기능은 하나씩 추가한다.
2. 코드 전체를 다시 만들게 하지 않는다.
3. 11주차 구조를 유지한 채 추출 함수와 분류 함수만 개선한다.
4. 완벽한 자연어 처리를 목표로 하지 않는다.
5. Groq API나 외부 도구는 선택 확장이다.
6. 실행 결과 파일을 남긴다.

---

## 12주차 구현 수준

이번 주 제출은 기본형만으로도 가능하다. 다만 4~7주차에서 배운 내용을 연결하고 싶은 학생은 중급형 또는 확장형으로 진행할 수 있다.

| 수준 | 설명 | 예시 |
| --- | --- | --- |
| 기본형 | 규칙 기반 추출과 분류 | 문자열 포함 여부, `if` 조건문 |
| 중급형 | Groq API로 추출 또는 정리 보조 | `extract_with_groq()`로 JSON 형태 추출 |
| 확장형 | 외부 API 또는 도구 1개 사용 | 날씨 API, 도서 검색 API, 환율 API, 로컬 파일 조회 |

중요한 원칙은 다음이다.

- 외부 도구가 실패해도 기본 실행은 가능해야 한다.
- API 키는 코드에 직접 쓰지 않는다.
- LLM이나 외부 도구가 모든 책임을 가져가면 안 된다.
- 함수별 입력과 출력은 코드에서 분명히 보여야 한다.

## 12.2 내 에이전트의 표 설계하기

일정공지 예시에서는 다음 열을 사용했다.

```markdown
| 제목 | 대상 | 날짜 | 해야 할 일 | 준비물 |
|---|---|---|---|---|
```

학생은 자기 주제에 맞게 열 이름을 바꾼다.

| 주제 | 권장 표 열 |
| --- | --- |
| 일정공지 | 제목, 대상, 날짜, 해야 할 일, 준비물 |
| 독서 추천 | 제목, 장르, 난이도, 추천 대상, 추천 이유 |
| 운동 루틴 | 목표, 난이도, 시간, 장비, 해야 할 운동 |
| 여행 계획 | 장소, 날짜, 예산, 활동, 준비물 |
| 학습 도우미 | 과목, 단원, 난이도, 해야 할 공부, 참고 자료 |

코딩에이전트에게 먼저 표 설계를 확인시킨다.

```
my_agent.py와 context.md를 읽어줘.
내 에이전트의 output.md 표에 들어갈 열을 정하려고 해.

내 에이전트 주제:
- 에이전트 이름:
- 입력 자료:
- 최종 출력:

일정공지 예시의 제목, 대상, 날짜, 해야 할 일, 준비물 열을 참고하되
내 주제에 맞는 Markdown 표 열 5개를 추천해줘.

아직 파일은 수정하지 마.
```

## 12.3 데이터 구조 정하기

사실 추출 결과는 다음처럼 단순한 딕셔너리 리스트로 둔다.

```python
[
    {
        "name": "예시 항목",
        "category": "분류 기준",
        "detail": "핵심 정보",
        "task": "해야 할 일",
        "note": "주의할 점",
    }
]
```

키 이름은 주제에 맞게 바꿔도 된다. 핵심은 다음 단계 에이전트가 읽을 수 있는 형태로 결과를 정리하는 것이다.

## 12.5 선택 확장: Groq API로 추출 보조하기

Groq API는 필수가 아니다. 입력 자료가 자유로운 문장이라 규칙 기반 추출이 너무 어렵다면 `extract_facts` 내부에 LLM 보조 함수를 추가할 수 있다.

권장 구조:

```python
USE_LLM = False

def extract_facts(text):
    if USE_LLM:
        return extract_with_groq(text)
    return extract_with_rules(text)
```

이 구조를 쓰면 API 키가 없거나 네트워크가 불안정해도 규칙 기반 fallback으로 실행할 수 있다.

코딩에이전트 요청:

```
my_agent.py의 extract_facts를 확장하고 싶어.

요구사항:
- 기존 규칙 기반 추출은 extract_with_rules 함수로 유지해줘.
- 선택적으로 Groq API를 쓰는 extract_with_groq 함수를 추가할 수 있게 구조를 나눠줘.
- USE_LLM = False가 기본값이어야 해.
- GROQ_API_KEY는 .env 또는 환경변수에서 읽고, 코드에 직접 쓰지 마.
- API 키가 없으면 규칙 기반 추출로 돌아가게 해줘.
- 아직 LangGraph는 사용하지 마.

먼저 수정 계획만 말해줘. 아직 파일을 수정하지 마.
```

## 12.6 선택 확장: 외부 도구 붙이기

외부 도구는 에이전트의 판단을 보조한다. 예를 들어 여행 에이전트라면 날씨 API를 참고하고, 독서 에이전트라면 도서 검색 API를 참고할 수 있다.

| 주제 | 외부 도구 예시 |
| --- | --- |
| 여행 계획 | 날씨 API, 환율 API |
| 독서 추천 | Open Library API, 로컬 도서 목록 파일 |
| 뉴스 요약 | RSS, 검색 결과 파일 |
| 학습 도우미 | 로컬 교재 파일, 사전 API |
| 식단 추천 | 영양 정보 API |

권장 구조:

```python
def fetch_external_context(query):
    """외부 도구나 API에서 보조 정보를 가져온다."""
    return {}

def extract_facts(text, external_context=None):
    ...
```

코딩에이전트 요청:

```
내 에이전트에 외부 도구 1개를 선택 확장으로 붙이고 싶어.

내 주제:
- 에이전트 이름:
- 붙이고 싶은 외부 도구/API:
- 이 도구가 보강할 정보:

조건:
- 외부 도구가 실패해도 python my_agent.py 기본 실행은 가능해야 해.
- API 키가 필요하면 환경변수로만 읽어야 해.
- fetch_external_context 함수를 따로 만들고, 기존 extract_facts 구조는 유지해줘.
- 외부 도구 사용 여부와 실패 여부를 터미널에 짧게 출력해줘.

먼저 수정 계획만 말해줘. 아직 파일을 수정하지 마.
```

## 12.8 분류 에이전트 개선

분류는 처음에는 단순한 규칙으로 충분하다. 일정공지 예시에서는 학년이나 사용자 유형으로 나누었다. 내 에이전트에서는 주제에 맞게 분류 기준을 정한다.

| 주제 | 분류 기준 예시 |
| --- | --- |
| 일정공지 | 전체 학생, 1학년, 4학년, 교환학생 준비생 |
| 독서 추천 | 초보 독자, 전공 학습자, 가벼운 독서 |
| 운동 루틴 | 초급, 중급, 고급 |
| 여행 계획 | 당일치기, 1박 2일, 저예산 |

코딩에이전트 요청:

```
classify_items 함수를 개선해줘.

규칙:
- facts 리스트를 입력으로 받는다.
- 내 에이전트 주제에 맞는 유형별로 항목을 묶은 dict를 반환한다.
- 복잡한 AI 판단은 하지 말고 문자열 포함 여부나 간단한 조건으로 분류한다.
- 분류 기준을 코드 안에서 읽기 쉽게 주석 또는 변수명으로 드러내줘.
```
